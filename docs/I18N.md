# Internationalisation (i18n) — how to add a locale

The IntelliPilot frontend uses Flutter's `gen-l10n` pipeline. Strings live in
ARB files under `assets/l10n/`; bindings are generated into
`lib/l10n/generated/`. The template locale is **English** (`intl_en.arb`) —
any string not translated in another locale falls back to the English value
at runtime.

## Files

```
l10n.yaml                          # pipeline config
assets/l10n/intl_en.arb            # template, exhaustive list of keys
assets/l10n/intl_de.arb            # German translations (partial)
lib/l10n/generated/                # auto-generated; never edit by hand
```

## Adding a new locale

1. Create `assets/l10n/intl_<code>.arb` (e.g. `intl_fr.arb`). The first line
   must be `"@@locale": "<code>"`.
2. Translate the keys you care about; omit the rest — they'll fall back to
   English. The pipeline reports the number of untranslated messages on
   each `flutter gen-l10n` run.
3. Run `fvm flutter gen-l10n`. The generated `app_localizations_<code>.dart`
   shows up under `lib/l10n/generated/`.
4. The new locale automatically joins `AppLocalizations.supportedLocales` —
   no router or `MaterialApp` change needed.

## Translation guidance

- Match the **tone** of `intl_en.arb`. Most strings are concise, action-
  oriented sentence case.
- Preserve ICU MessageFormat placeholders verbatim
  (`{name}`, `{count, plural, one{…} other{…}}`).
- Keep ARB metadata (`@key`) blocks in English — they document keys for
  future translators, not end users.
- When a key adds a placeholder, double-check every existing locale's value
  still includes the same placeholder; otherwise `gen-l10n` errors.

## Adding a string

1. Add the key + value + `@key` description block to `intl_en.arb`.
2. Run `fvm flutter gen-l10n` so the typed getter exists.
3. Add translated values to any locale that wants to ship the new string.
4. Use the getter from a widget: `AppLocalizations.of(context).yourNewKey`.

## Audit notes (Phase 15)

- The German file (`intl_de.arb`) ships translations for the most-visible
  surfaces (page titles, primary CTAs, status chips, the request-access
  flow, palette and shortcut hints). Roughly 370 keys remain English-only
  and will be filled in incrementally.
- Hardcoded strings: `flutter analyze` won't catch literal user-facing
  strings. Manual sweep verified that the auth, projects, board, wiki, and
  palette surfaces route through `AppLocalizations`.
- Plurals use ICU MessageFormat (see `historyEntryHeader`,
  `milestoneCloseSummary` in `intl_en.arb` for the canonical examples).
- Dates: short timestamps render via `DateTime.toLocal()` + manual
  formatting today. Switching to `intl`'s `DateFormat` is a Phase 17 polish
  item (and will gain proper German formatting for free).
